## Redirect invariants

- No product redirect activates before its target deployment, authenticated and
  unauthenticated journeys, state-transfer requirement, and rollback gate pass.
- Redirects preserve path and query by default, except authentication routes,
  which copy only allow-listed auth parameters and a validated relative return.
- No callback or return parameter may resolve to another origin or a `//` path.
- Legacy callbacks and recovery URLs remain handlers, not blind redirects, until
  the observation ledger proves issued links have aged out.
- `308` is used for durable page-family moves only after compatibility gates;
  temporary/cohort routing uses reversible controls.
- Every activated row gains deployment ID, timestamp, browser/curl proof, rollback
  action, and observation result before its status changes to Done.
