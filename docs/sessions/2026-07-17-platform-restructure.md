# Platform restructure baseline

- Date: 2026-07-17
- Area: Four-application platform restructure
- Problem: The current combined application and Admin deployment need a verified migration path to Portfolio, Studio, Admin, and Auth without disrupting production behavior.
- Status: PLATFORM-00 remains open for its final proof gates and PLATFORM-08 is in progress under the approved app-first execution sequence. Portfolio and Studio production/staging subdomains are configured additively without moving the apex. The latest single-hop redirect fix is committed, but Vercel's 24-hour build-rate limit blocks its deployment and therefore blocks apex cutover.
- Decisions: Keep the existing root Vercel project live until Portfolio cutover; dark-launch Portfolio first; expose the existing product hub as Studio second; perform the apex cutover only after both validate; and complete shared Auth/SSO last. Use one program PR with reviewable commits. Preserve e-commerce projects outside the migration.
- Evidence: The canonical Supabase project, current Vercel projects, current Cloudflare records, and hosted Auth URL/provider settings were read without exposing secrets. Read-after-write checks confirmed the values and that Google/email remain enabled. A non-user hosted recovery request accepted the production callback with HTTP `200`. Vercel read-back checks confirmed current Development URLs, canonical Production URLs, branch-specific staging URLs, dynamic generic Preview behavior, and Supabase-variable coverage. The persistent remote `staging` branch was created from the verified `origin/main` baseline. Portfolio and Main both pass focused TypeScript, zero-warning ESLint, and production builds. Local browser validation confirmed the complete Portfolio, mobile Portfolio navigation, Studio inventory, Studio-specific navigation, product-link handoff, current-root compatibility, and no captured console errors. The new Portfolio Vercel project has complete least-privilege environment coverage without a service-role key. Cloudflare and Vercel confirm exact DNS configuration for both new subdomains. Studio HTTPS renders the tested inventory deployment while apex behavior remains unchanged. Portfolio now has stable fresh TLS across both edge addresses and protocols; repeated HTTPS and deployed route/API checks pass. Local production redirect smoke verifies single-hop Portfolio content aliases and method/query-preserving Studio compatibility redirects.
- Files changed: New independent `apps/portfolio` application and public-only integration boundary; public Blog, Resume, sitemap, `llms.txt`, not-found, and error surfaces; Portfolio-to-Studio compatibility redirects and redirect ledger; corrected Portfolio/Studio Vercel ownership and Development-port contract; Studio hostname detection (including Vercel's server-provided deployment hosts), inventory, metadata, navigation, and local-port compatibility; repository-local Vercel and Cloudflare tooling; PDF binary Git handling for copied portfolio credentials; platform URL helpers; platform decision log; proof ledger; implementation-guide status/order; repository environment task inputs; and this session entry.
