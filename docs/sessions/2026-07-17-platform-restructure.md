# Platform restructure baseline

- Date: 2026-07-17
- Area: Four-application platform restructure
- Problem: The current combined application and Admin deployment need a verified migration path to Portfolio, Studio, Admin, and Auth without disrupting production behavior.
- Status: PR #39 merged to `main` as `4703e7c83d0b92935dc8dd10a3535a2f7d51a426`, and the Portfolio, Studio, and Admin production deployment checks passed. PLATFORM-00, PLATFORM-07, PLATFORM-08, and PLATFORM-09 remain open for uncompleted authenticated-browser, rollback, observation, and controlled-Production gates; PLATFORM-10 has started from the stable content-ownership boundary. ADR-006 now limits the platform to localhost Development, Vercel-managed Preview, and final-domain Production. The application moved directly from `apps/jayantgoyal`/package `jg` to `apps/studio`/package `studio`; the existing Vercel project is now `jayantgoyal-studio` rooted at `apps/studio`; and the apex/`www` domains now belong to Portfolio. - Decisions: Portfolio, Studio, and Admin folder/package/filter identities must match exactly (`portfolio`, `studio`, `admin`). The application names are `Portfolio`, `Studio`, and `Admin`; the searchable public identity is `Jayant Goyal`; and the app-level metadata identities are `Jayant Goyal`, `Studio by Jayant Goyal`, and `Admin by Jayant Goyal`. Repeated page titles stay functional and concise: Portfolio pages use `%s | Jayant Goyal`, Studio pages use `%s | Studio`, and Admin pages use `%s | Admin`; ownership wording is not repeated on pages such as Users, Deployments, Hero, or Weather. `JG` is reserved for visual or legacy technical identifiers, not written application branding. These values live in a dependency-free `@repo/brand` package consumed by every app. Proven visual mechanics now belong in `@repo/ui`: the application sidebar frame, brand header, top header, breadcrumb trail, ordinary navigation-section renderer, theme and motion providers, loading primitives, and auth presentation building blocks. App-owned adapters still decide Portfolio scroll sections, Studio nested products and session state, Admin role-gated sections, dynamic breadcrumb meanings, and all authorization. Shared Auth/SSO session ownership remains last. Studio is a single-purpose application on every host rather than a dual Portfolio/Studio surface; Portfolio-owned legacy paths redirect to the canonical Portfolio origin. PR #39 used the original one-program-PR strategy; ADR-005 governs focused post-merge PRs. E-commerce projects remain outside the migration.
