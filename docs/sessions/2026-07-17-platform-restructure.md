# Platform restructure baseline

- Date: 2026-07-17
- Area: Four-application platform restructure
- Problem: The current combined application and Admin deployment need a verified migration path to Portfolio, Studio, Admin, and Auth without disrupting production behavior.
- Status: PLATFORM-00 remains open for its final proof gates and PLATFORM-08 is in progress under the approved app-first execution sequence. The independent `apps/portfolio` boundary and the hostname-aware Studio inventory compatibility slice are implemented and locally verified; deployments and domain attachment are pending.
- Decisions: Keep the existing root Vercel project live until Portfolio cutover; dark-launch Portfolio first; expose the existing product hub as Studio second; perform the apex cutover only after both validate; and complete shared Auth/SSO last. Use one program PR with reviewable commits. Preserve e-commerce projects outside the migration.
- Evidence: The canonical Supabase project, current Vercel projects, current Cloudflare records, and hosted Auth URL/provider settings were read without exposing secrets. The scoped Management API patch updated `site_url` and `uri_allow_list`; the recovery template was then corrected from `{{ .SiteURL }}` to `{{ .RedirectTo }}` so it honors the application's exact callback. Read-after-write checks confirmed the values and that Google/email remain enabled. A non-user hosted recovery request accepted the production callback with HTTP `200`. Vercel read-back checks confirmed current Development URLs, canonical Production URLs, branch-specific staging URLs, dynamic generic Preview behavior, and Supabase-variable coverage for both existing projects. The persistent remote `staging` branch was created from the verified `origin/main` baseline. Portfolio and Main both pass focused TypeScript, zero-warning ESLint, and production builds. Local browser validation confirmed the complete Portfolio, mobile Portfolio navigation, Studio inventory, Studio-specific navigation, product-link handoff, current-root compatibility, and no captured console errors.
- Files changed: New independent `apps/portfolio` application and public-only integration boundary; Studio hostname detection, inventory, metadata, navigation, and local-port compatibility; repository-local Vercel and Cloudflare tooling; PDF binary Git handling for copied portfolio credentials; platform URL helpers; platform decision log; platform URL/environment contract; proof ledger; implementation-guide status/order; repository environment task inputs; and this session entry.
- Risks: Current OAuth uses a `next` query parameter in `redirectTo`, so the temporary same-origin wildcard callback paths remain until the code moves the validated destination into an httpOnly handoff cookie. Do not run an unrestricted `supabase config push` from the normal worktree.
