# Media Converter Utility

- **Date:** 2026-07-22
- **Area:** Studio / utilities
- **Problem:** Add a Studio utility that accepts YouTube video or Shorts links and offers MP3 or MP4 downloads for content the user owns or is authorized to download.
- **Current approach:** Work is isolated in the `codex/media-converter` worktree. Seven `.env*` files were copied from the protected source checkout, and the local Supabase stack ID is unique to this worktree. The Studio utility and private worker are implemented and validated; the reviewed migration is live, and worker hosting is the remaining deployment step.
- **Key decision:** The feature will include an explicit rights/permission safeguard and will not present downloading as permission to copy protected media.
- **Platform constraint:** Current YouTube policies prohibit third-party apps from downloading audiovisual content or separating audio, so arbitrary YouTube-link extraction will not be implemented. Users can download their own uploads through YouTube Studio and convert the resulting file.
- **Superseded prototype:** The first implementation used lazy `@ffmpeg/ffmpeg` browser conversion to avoid Vercel functions. Runtime browser QA exposed a CDN engine-fetch failure, and the user chose the private Python worker architecture documented below instead.
- **Implemented:** Registered `/tools/media-qr/media-converter` in the Tech Tools catalog with metadata, sitemap/breadcrumb discovery through the existing tool registry, and complete reference/FAQ content.
- **Conversion flow:** Added drag/drop and file selection, 500 MB and media-type validation, MP3/MP4 output, three quality levels, lazy FFmpeg loading, progress, cancel, preview, download, and object/virtual-file cleanup. MP4 is limited to video sources; MP3 accepts audio or video.
- **YouTube flow:** Added normal-video and Shorts URL recognition only to guide owners to YouTube Studio's official MP4 download workflow. The page clearly states that arbitrary YouTube extraction is not enabled.
- **Tests:** Added focused pure-function coverage for validation, output naming, FFmpeg command construction, media detection, and YouTube URL classification.
- **Style:** Formatted the new route, helpers, tests, catalog/reference updates, dependency manifests, and this session entry with the repository's Prettier configuration.
- **Diff hygiene:** Reverted whole-file formatting churn in the pre-existing tool catalog and reapplied only the new icon and catalog entry.
- **Dependency hygiene:** Restored the existing lockfile formatting and regenerated only the lock entries required by the two FFmpeg browser packages.
- **Documentation hygiene:** Reverted unrelated Markdown spacing changes and retained only the new Media Converter capability notes.
- **Validation:** A full frozen-lockfile workspace install restored worktree package links. Studio lint and type checking pass, and the focused Media Converter plus SEO registry suites pass (7 tests).
- **Baseline note:** The first test command accidentally invoked the full Studio suite because arguments after the package script's `--` were ignored; unrelated suites then failed before collection while workspace links were incomplete. The correctly scoped suites pass after the full install.
- **Runtime QA adjustment:** Browser testing showed that a styled label targeting a visually hidden file input was not reliably exposed to automated file-chooser handling. Replaced it with a visible styled native file input, improving keyboard, assistive-technology, and automation interoperability.
- **Error recovery:** Runtime testing also showed that FFmpeg failures were only visible in a transient toast. Added a persistent inline error state that resets on retry, file changes, and cancellation.
- **Direction change:** After reviewing Vercel's immutable 4.5 MB Function payload limit, the browser-only implementation is being replaced with a private asynchronous worker. Studio will exchange only small job JSON; generated media will travel directly from the worker to private object storage and from storage to the browser.
- **Queue/storage contract:** Added a reviewed migration for user-scoped `jg_app.media_conversion_jobs`, atomic worker job claiming, stale-job recovery, expiry cleanup claiming, RLS, and a private `media-converter-output` bucket. The migration is intentionally not applied remotely until the worker and Studio integration have passed local validation.
- **Shared job contract:** Replaced the browser-file FFmpeg helpers with strict YouTube URL normalization, MP3/MP4 and quality validation, public job DTO mapping that omits storage paths and user IDs, active-state detection, and server-only owner allowlist checks. Production fails closed when no email or user-ID allowlist is configured; local development remains usable without production credentials.
- **Studio API boundary:** Added authenticated, same-origin job creation, recent-job recovery, per-job polling, and five-minute signed-download endpoints. Every query remains user-scoped under RLS, production access is checked against the private allowlist, only one active job is allowed per user, and the large media file never crosses a Vercel Function response.
- **Python worker:** Added a Dockerized Python 3.12 queue consumer with pinned FastAPI/httpx/yt-dlp dependencies plus FFmpeg and Deno. It validates and canonicalizes YouTube-only links, rejects live/upcoming or overlong media, caps output size, supports MP3 at 128/192/320 kbps and MP4 up to 480p/720p/1080p, reports throttled progress, and never accepts public job submissions.
- **Large-file path:** Implemented direct 6 MB TUS chunks from the worker to Supabase Storage with retry/resume offsets, followed by user-scoped signed downloads. Completed outputs default to a 60-minute lifetime; cleanup removes the Storage object before deleting its job record. Optional base64-encoded owner cookies are materialized with mode `0600` and never logged.
- **Studio experience:** Replaced file upload and browser-WASM controls with a URL-first owner workflow, MP3/MP4 and bounded quality choices, persistent job recovery, two-second progress polling, terminal error/expiry states, recent private history, and signed-download activation. The page explains the direct-to-storage boundary and disables duplicate submissions while a job is active.
